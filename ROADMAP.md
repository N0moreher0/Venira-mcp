### P0 — Security evidence and correctness

1. **Shell policy adversarial coverage** (in progress)
   - Added `test:shell-policy-adversarial`: 114 table-driven cases with stable ids covering root/home delete spellings (`//`, `/./`, `~/`, `"$HOME"`, `${HOME}`, `-fr`, `-r -f`, `--recursive --force`), quoting/escapes, command paths and wrappers for privilege escalation, protected-file globs/character classes, and write-then-run sequences. Every hard-deny case asserts `deny` in balanced and `ask` in permissive; non-regressions cover workspace `rm`, broad globs and safe commands.
   - Hardened `root_delete` and `privilege_escalation` to evaluate parsed segments (not just raw regex), added PowerShell `Start-Process -Verb RunAs`, made protected-file glob matching specificity-aware (`*.env` and `.e[n]v` deny; `cat *`/`cat *.json` do not), gated `tsx`/`ts-node` like `node`, and added a filesystem-root hard deny (`rm -rf /`, `rm -rf C:\`, `Remove-Item -Recurse -Force $HOME`, …) so a broad destructive delete cannot run in `permissive` via the Windows `Remove-Item` family.
   - Remaining: add a stable case id for every newly reported spelling. Resolved this session: interpreter/script execution (`bash ./probe.sh`, `pwsh -File …`, `node ./probe.js`, `cmd /c *.bat`, `tsx ./probe.ts`) now has stable cases `policy_adv_just_written_executable_*` and is classified as dynamic execution / unclassified → `ask` in balanced; write-then-run was already covered by `policy_adv_write_then_run_requires_approval`. No policy change was needed, so just-written targets still require approval; permissive remains operator opt-in. False asks were measured with `npm run measure:shell-asks` (173-command corpus, env-isolated): balanced asked on 131/145 benign commands (90.3%), worse than strict (92/145), because balanced never consulted an allowlist. A narrow read-only tier (`balanced.read_only`: inspect commands and read-only git (`status|log|diff|show|blame|grep|cat-file|ls-tree|rev-list|merge-base|for-each-ref|ls-files|rev-parse|shortlog|describe`, `remote -v`, `stash list|show`, `config --get`, `tag -l`, `branch --list`, `-C <dir inside the workspace>`) and `npm ls|outdated|view`; no redirects, background or substitution; workspace-bound paths; flag guards for `find -delete/-fprint`, `sort -o`, `rg --pre`, `git -c/-C/--output/--no-index`) brings it to 88/145 (60.7%) with 0 missing asks (`test:balanced-read-only`, 368 checks). The same git guard now covers the older `safe_command` path, which used to allow `git -c core.fsmonitor=… status`. A second tier, `balanced.local_dev`, allows build/test (`npm|pnpm|yarn` scripts with conventional names whose current body, `pre`/`post` hooks and nested scripts pass a conservative scan; `cargo build|test|check|clippy|fmt --check`, `go build|test|vet`, `dotnet build|test`, `pytest`, `ruff check`) and reversible git branch/stash (`checkout -b`, `switch`, `stash [push|apply|pop]`, `restore --staged`) under the same containment rules, bringing balanced to 66/145 (45.5%) with 0 missing asks. A third tier, `balanced.workspace_write`, allows `mkdir|touch|cp|mv|tee|chmod`, simple `sed -i 's/a/b/'`, create-only `tar`, PowerShell `New-Item|Copy-Item|Move-Item|Set-Content|Add-Content|Out-File`, cmd `copy|move` and `>`/`>>` redirects only when every target resolves inside the workspace (symlink-safe, using the file tools' `resolveWithin`/`isProtectedPath`), is not the workspace root and is not a build/config/hook file (`package.json`, lockfiles, `Makefile`, `Cargo.toml`, `tsconfig*`, `*.config.*`, `.git/`, `.github/`, `.husky/`, `node_modules/`, …); brace expansion, `~`, variables, `SymbolicLink|Junction|HardLink` item types and setuid/world-writable `chmod` modes keep asking. A fourth tier, `balanced.install`, allows lockfile-faithful installs with lifecycle scripts disabled (`npm ci|install --ignore-scripts`, `pnpm|yarn` equivalents, `go mod tidy|download|verify`, `dotnet restore` of an in-workspace path) plus read-only `pip list|show|freeze|check` and `diff|cmp|fc` on workspace paths. Null sinks (`/dev/null`; `$null` and `nul` only in PowerShell/cmd) are now dialect-aware (`isNullSink` in `shell-parser.ts`) and no longer trip `writes_outside_workspace` or `unresolved_file_argument`, so `ls 2>/dev/null` stays read-only while `ls > $null` in bash and `ls 2>/dev/null > ../x` still ask. Balanced was 39/144 (27.1%) before the single-file delete tier below; it is now 36/144 (25.0%) with 0 missing asks (`test:balanced-read-only`: 1098 checks; adversarial suite 114; policy corpus 273). `git restore <file>...` (explicit plain in-workspace files that are not build/config/hook/protected) is allowed under `balanced.local_dev` by owner decision: it can overwrite uncommitted edits, accepted because `project_snapshot` checkpoints make that recoverable (the policy itself cannot create a checkpoint, so `opShellRun` does it right before spawning via `lib/restore-checkpoint.ts`: the overwritten workspace paths are stored with `opSnapshotCreate` and reported as `checkpoint` {id, paths, reused, restore_with} in the shell result; explicit files already held byte-for-byte by an existing checkpoint are reused instead of consuming a `VENIRA_SNAPSHOT_KEEP` slot; the command does NOT run and fails with `checkpoint_failed` when the checkpoint cannot be stored; `restore --staged` alone needs none; covered by `test:restore-checkpoint`, 10 checks, which pins the store with `VENIRA_SNAPSHOT_DIR` because checkpoints do not live under `VENIRA_DATA_DIR`). Directories, `.`, globs/pathspecs, `--source`, `-p`, `--staged --worktree`, the `--` separator and anything after a `cd` keep asking. `npx` is allowed only for `tsc|vue-tsc|vitest|jest|mocha|eslint|prettier` whose bin already exists in the workspace's `node_modules/.bin` (flags limited to `--no-install|--no`, judged exactly like the bare tool, rule `balanced.local_dev`), so it can never download or pick a package (`npx tsc` without a local TypeScript would fetch the unrelated `tsc` package); `tsc|vue-tsc` with `--init|--watch|-w|--clean|--generateTrace` keep asking, and the older `safe_command` path now only accepts `npx --no-install <tsc|esbuild|tsx|vitest|jest|eslint|prettier>` instead of any local bin with any arguments. A read-only container tier (`lib/shell-policy-balanced-docker.ts`, rule `balanced.read_only`) allows `docker|podman ps|images|image ls|container ls|compose ps` with list flags only; `logs` (container output can contain secrets), remote daemons (`-H`, `--context`, `DOCKER_HOST=`), `--format`/`--filter`, `inspect`, `cp`, compose `-f` and anything mutating keep asking, and `nerdctl` is not covered. Still open, each needing its own design: network git (`fetch|pull|clone`), recursive deletion (`rm -rf`, `Remove-Item -Recurse`, `rmdir /s` keep asking; single files are covered by `balanced.workspace_delete`), installing new packages (`npm install <pkg>`, `pip install`, `cargo add`), `git checkout <branch>`, and running project code directly (`node x.js`, `python -m pytest`, `make`, `npx tsx x.ts`). The former `safe_command` gap is closed: `devToolFlagsOk` (shared by the older `safe_command` path and `balanced.local_dev`) now makes `eslint --fix*`, `prettier --write|-w` (including `-lw` clusters and `--write=…`) and any `--config`/`-c`/`--rootDir`/`--root`/`--output-file`/`--ignore-path`/`--plugin` value that is absolute, `~`/drive-prefixed, escapes with `..`, contains variables/globs, is an inline JSON string or is missing ask in balanced, while plain runs (`eslint .`, `prettier --check .`, `jest --config jest.config.js`) stay allowed; covered by `policy_adv_dev_tool_*` (20 cases) and false asks unchanged at 39/144 (27.1%).
    - Open directions, measured 2026-11-08 (`measure:shell-asks`, balanced 39/144 false asks; the audit log stores no command text, so the corpus is the only data): run project code 10, package install 9, network 6, build/test 3 (`python -m pytest`, `make test`, `gradle test`), deletion 7 (3 single files, 4 recursive), PowerShell/cmd read-write 7. Decision: the only direction whose damage stays inside the workspace and is recoverable is **deleting explicit single files**; running project code, installing new packages and network git stay on `ask` by design because they execute or fetch code the workspace does not contain, and `git checkout <branch>` stays on `ask` because it rewrites the whole working tree.
    - Landed: `balanced.workspace_delete` (`lib/shell-policy-balanced-delete.ts`) allows `rm <file>...` (POSIX flags `-f|-v` only), PowerShell `Remove-Item|ri|rm|del|erase` (`-Path|-LiteralPath|-Force` only; abbreviations such as `-r` keep asking) and cmd `del|erase` (no switches; `del /f /q` is stopped earlier by `destructive_delete`) for explicit operands that resolve inside the workspace, are not protected/build/config/hook files, are not globs/lists/`~`/variables/`file:stream`, and are regular files (directories and symlinks ask; a missing operand is a no-op), never after a `cd` and never as `./rm`. Like `git restore <file>`, it runs only after `opShellRun` stores a checkpoint of the files it will delete (`deleteTargets` in `lib/restore-checkpoint.ts`; `git restore a; rm b` shares one checkpoint; fail closed with `checkpoint_failed`; bytes already held by a checkpoint are reused). Recursive deletes (`rm -rf dist`, `Remove-Item -Recurse`, `rmdir /s`) keep asking. Pinned by `test:balanced-read-only` (section 2e, 1098 checks) and `test:restore-checkpoint` (15 checks). Measured: balanced false asks 39 → 36/144 (25.0%), missing asks 0/29, policy corpus 273/273, `verify` 518 checks.
    - Landed: `python|python3|py -m pytest|mypy` (`lib/shell-policy-python.ts`) is exempt from `dynamic_execution` and allowed under `balanced.local_dev` when the command is bare, no flag can load code or redirect paths (`-p`, `-c`, `-o`, `--rootdir`, `--confcutdir`, `--basetemp`, `--junitxml`, `--config-file`, ... including glued forms), nothing follows a `cd`, and the workspace root holds no `pytest.py`/`pytest/`/`_pytest*` (or the mypy equivalents) that `python -m` would import instead, since the cwd leads `sys.path`. `python -m unittest|http.server|pip|venv`, `-c` and scripts still ask; `strict` still asks for every `python <module|script>`. Pinned in `test:balanced-read-only` section 2f (1183 checks). Measured: balanced false asks 36 \u2192 35/144 (24.3%), strict unchanged at 91/144, missing asks 0/29.
    - Left on `ask` by design (measured, not added): running project code, installing new packages, network git and `git checkout <branch>` (see the decision above); recursive deletes. Reopen one only with a concrete design that keeps the damage inside the workspace.
2. **Shell policy parsers** (in progress)
   - Separate POSIX, PowerShell, and cmd parsing while preserving Windows backslashes and current safe behavior.
   - Landed so far: `lib/shell-dialect.ts` (`posix` / `powershell` / `cmd` resolver), `ParsedCommand.dialect`, `parseShellCommand(raw, { shell })`, `evaluateShellCommand(..., { shell })` and `shellOverrideMatches(..., shell)`; the tool layer now threads the selected shell into the policy gate and override checks.
   - Adversarial coverage added for per-dialect classification (`policy_adv_dialect_*`); the targeted adversarial suite passes 114 checks and the TypeScript build passes after the PowerShell escape fix below. Full cross-dialect parser rewrite (PowerShell verb-noun parameter model, cmd batch flags) remains open.
   - This session landed the cmd.exe delegation layer: `cmd /c <command>` (and `/k`) is unwrapped at parse time to the inner command (`del /f /s /q …`, `git push`, `npm publish`, `powershell -enc …`) while script targets (`*.bat`, `*.ps1`, …) keep the dynamic-execution gate; destructive-delete flag matching no longer uses a leading word boundary that never matched `-Recurse`, `-Force`, `/f`, `/s`, `/q`. New adversarial cases cover the unwrap (`policy_adv_dialect_cmd`). Interpreter + script execution (`bash ./probe.sh`, `python3 ./probe.py`) requires approval via `policy_adv_just_written_executable_*`. PowerShell backtick escapes now decode before policy matching, preventing escaped sensitive names such as `.e`nv from bypassing protected-file checks; regression coverage is in `policy_adv_dialect_powershell`. The exhaustive cross-dialect grammar (PowerShell verb-noun parameter model, cmd batch flags) remains open.
   - Landed: PowerShell colon-form parameters (`lib/shell-powershell-params.ts`, wired into `parseShellCommand` for the `powershell` dialect). `-Name:value` is the same parameter as `-Name value`, but the rules only looked at separate argv entries, so the glued spelling hid the operand. Measured before the fix (balanced): `Get-Content -Path:.env`, `Get-Content -LiteralPath:.env` and `Select-String -Path:.env` were **allowed** (`balanced.read_only`), and `Remove-Item -Path:C:\ -Recurse -Force`, `-LiteralPath:C:\ -Rec -Fo`, `-Recurse -Force -Path:$HOME` and `Remove-Item -Path:.env` only asked instead of being hard-denied. The parser now splits `-Name:value` into `-Name`, `value` for cmdlets (verb-noun names) and a short list of well-known aliases only; external programs keep their own convention (`dotnet build -p:Configuration=Release` is unchanged), and switch values (`-Force:$true`, `-Recurse:$false`) reduce to the bare switch, which can only make the policy stricter. Because policy and `deleteTargets` share `parsed.segments`, `Remove-Item -Path:file` is now judged and checkpointed exactly like `-Path file` (so it is allowed under `balanced.workspace_delete` with a checkpoint; `-Path:*.log`, `-Path:../x`, `-Path:package.json` and `-Recurse:$true` keep asking). Pinned by `policy_adv_dialect_powershell_colon_params` (`test:shell-policy-adversarial`, 115 checks), `test:balanced-read-only` (1189 checks) and a colon-form checkpoint round trip in `test:restore-checkpoint` (16 checks). Measured: balanced false asks unchanged at 35/144 (24.3%), strict 91/144, missing asks 0/29, `verify` 518 checks. Still open and not yet probed: cmd batch flag spellings (e.g. clustered or `/`-glued forms) and PowerShell parameter abbreviations beyond the ones covered by the existing flag regexes (`-Rec`, `-Fo` are already denied).

## Product capability candidates

These are not commitments; prioritize only with demonstrated demand:

- Atomic multi-file patch application with dry-run and snapshot integration.
- Dry-run support for write/edit/delete, plus safe move/copy operations.
- Shell output streaming/resume and stdin support.
- Optional automatic checkpoints for large edit workflows.
- Tree-sitter-backed symbol parsing and ripgrep-backed search when available.
- Broader compiler/test error explainers.
- MCP resources/prompts for health and audit workflows.
- Restrictive project-local policy that can only add ask/deny rules.
- Local aggregate latency and ask/deny telemetry with no raw arguments.
- Native integration only if a supported host/runtime requires it; the typed corehost adapter already exists.
